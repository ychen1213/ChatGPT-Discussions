## 回答

## 一、我的选型结论

重新阅读你提供的[非周期复杂三维 Mark 开源 FDTD 调研报告](2026-10-26_非周期复杂三维Mark开源FDTD与Lumerical对比调研.md)，再结合你最近已经完成的 Meep 非均匀网格 S2 开发，我的建议是：

**如果我们把“原生非均匀网格、真实三维复杂形貌、减少大规模计算量”放在最高优先级，那么我更倾向于选择 FDTDX 作为未来的主求解器开发基础，而让 Meep 担任独立验证基准和 CPU/MPI 备用后端。**

但这一建议有一个重要前提：公司必须有可实际使用的 Linux GPU 计算环境，而且 FDTDX 要通过我们的真实材料与形貌精度测试。**这两个条件目前还没有得到实测证明，所以我不建议现在直接废弃 Meep。**

| 软件 | 角色 | 主要理由 |
|---|---|---|
| **FDTDX** | 长期主计算后端候选 | 原生三轴非均匀网格、GPU、可编程材料和形貌，减少内核改造的起步成本。 |
| **Meep FDTD** | 成熟参考与备用后端 | 光学电磁功能成熟，CPU/MPI 和复场分析有优势，但官方内核缺少三轴渐变网格。 |

这与 10 月 26 日报告中“Meep 优先”的结论有所不同，不是报告有根本错误，而是**选型权重发生了变化**：你现在明确把非均匀网格列为第一优先级，并且实际启动了 Meep 核心改造。我们也因此更清楚地看到了补齐这一能力的成本。

如果公司只能使用目前的原生 Windows CPU 环境，没有 Linux GPU 或可用的多 GPU 资源，那么我的判断会反过来：**Meep 更适合作为能够实际落地的主要后端。** FDTDX 在这种环境下的关键 GPU 优势无法发挥，而 Meep 在 Linux 上已有成熟的单模型 MPI 路线。

## 二、两款软件真正决定选型的差别

| 我们的核心需求 | Meep 1.35.0 | FDTDX 0.6.3 | 对课题的影响 |
|---|---|---|---|
| 三轴非均匀网格 | 官方内核不支持；目前 S2 是独立开发测试版 | **原生支持** RectilinearGrid | FDTDX 优势明显 |
| 斜面、曲面亚像素处理 | 成熟的介质亚像素平均 | 已有填充分数、有效张量处理，但适用性取决于几何输入 | Meep 成熟度占优，FDTDX 有直接可用的基础 |
| 有损与色散材料 | 完整的 Drude/Lorentz 求解能力 | 已有 Drude/Lorentz 及相关 ADE 更新 | 两者均可作为基础 |
| 色散界面共形 | 只平滑瞬时部分 | 部分材料与张量组合受限制 | **两者都不能跳过独立精度验证** |
| 复杂 STL 三维形貌 | 原生 Mesh 导入 | 需要额外 STL→体素/材料输入适配 | Meep 更方便 |
| GDS 参数化侧壁 | 可编程生成 | 已有 GDS、侧壁角和部分亚像素处理 | FDTDX 更方便 |
| 频域复场、反射角谱 | 功能成熟 | Phasor、FieldProjection 等接口已存在 | Meep 工程成熟度较高 |
| 单个大型模型 MPI | **Linux 上成熟支持** | 没有等价的传统 MPI chunk 接口 | Meep 有优势 |
| GPU | 官方不支持 | **JAX GPU 与多设备能力** | FDTDX 有优势 |
| 原生 Windows NVIDIA GPU | 不支持 | JAX 不支持 | 两者均无现成路线 |
| 长期核心算法维护 | C++ 内核，改造涉及多个模块 | Python/JAX，相关功能较易组织 | FDTDX 在新功能迭代上有一定优势 |

这里还需要指出，FDTDX 在 **2026 年 10 月 9 日发布的 0.6.3** 中，已经明确纳入了非均匀网格、非均匀 PML、GDS 亚像素平滑、斜侧壁几何、场投影和相应的数值修复。这些不是只有路线图、尚未发布的设想：[FDTDX 0.6.3 发布记录](https://github.com/ymahlau/fdtdx/releases/tag/v0.6.3)。

但正式发布不等于已经通过我们所要求的弱散射和相位精度验收。

### 1. 非均匀网格是两者最大的分水岭

FDTDX 的 RectilinearGrid 可以直接使用三个方向的物理坐标数组，统一计算场更新的距离、网格体积、监视器积分权重等。

你现在在 Meep 上做的 S2 开发，本质上就是在补这个能力。

但当前 S2 还没有接入 PML、激励源、频域监视器、完整材料界面和 MPI。即使 S2 的七套测试都通过，也不能据此认为已经拥有一个完整的非均匀 Meep 求解器。

因此，**如果继续使用 Meep，研发工作中会有相当一部分变成维护和验证电磁求解器底层；使用 FDTDX，则可以把更多精力放在 Mark 形貌、材料、光学信号和误差模型上。**

这就是我更倾向 FDTDX 的主要原因。

### 2. FDTDX 的亚像素处理已经比一般印象中完善，但还有重要限制

FDTDX 0.6.3 的 GDSLayerObject 支持通过 supersampling 估计材料填充分数，并且能够结合界面法向构建有效介电张量；对于倾斜界面，还可以选择保留非对角项。

而 Meep 的亚像素平滑已有较成熟的理论和实践经验，但其色散材料部分仍然有明确限制。

这里对我们有一个特殊问题：

你实际的复杂三维形貌不一定来自 GDS，而可能来自 SEM/TEM 重建、VDATA 和 STL。

FDTDX 能导入二值体素，不等于它会自动知道每个体素内部真实界面的填充分数和法向。

例如原始 VDATA 的体素尺寸是 20 nm，即使 FDTD 网格加密到 5 nm，也不会自动产生原始数据没有提供的 5 nm 几何信息。

因此，**真正困难的是将重建的三维界面正确映射到非均匀 Yee 网格上。** 这项工作对两款软件都重要，只是实现路径不同。

### 3. Meep 的 MPI 优势不能忽略

Meep 通过 MPI 将一个模型划分给多个进程，可以将电磁场存储分散到多个节点的内存中。这对于单模型占用数十甚至数百 GB 内存的情况非常重要。

FDTDX 具有 JAX 多 GPU 和 sharding 能力，但不能把它直接等同于 Meep 已经成熟的 MPI 域分解。尤其需要验证非均匀网格、有损材料、PML 和复杂三维形貌同时启用时的实际多设备表现。

两者的区别可以概括为：

- Meep：更适合已有大容量 CPU 内存和 MPI 集群的计算环境。
- FDTDX：更适合可用 NVIDIA GPU、希望快速开展三维数值计算及后续可微优化的环境。

**如果模型不能放进实际可用的 GPU 显存，GPU 速度优势就没有意义。** 多 GPU 可能解决部分容量问题，但也需要实际测试，而不能直接按显存相加估算可解规模。

## 三、还有一个容易被忽略的差异：项目的长期可维护性

我们要开发的不是通用商业 FDTD 软件，而是一套专门针对 Alignment/OVL Mark 的建模、仿真和测量信号平台。

假设今后要研究：

- 一条侧壁在不同高度和沿条纹长度方向的非对称变化；
- SEM/TEM 重建形貌导致的相位与偏振变化；
- 在特定波长、NA、光斑和偏振组合下的测量灵敏度；
- 通过形貌参数反推 alignment 信号误差。

FDTDX 的 JAX 架构可以方便地与 Python 数值分析、参数扫描和自动微分研究结合。但是要注意，JAX 支持自动微分不代表**所有色散、非均匀网格与自定义材料组合都已经支持稳定且准确的梯度**。

Meep 也完全能够用 Python 组织这些流程。区别不是 Python 能不能用，而是你是否需要持续修改 FDTD 内核。

另外，FDTDX 使用 MIT 许可证，Meep 使用 GNU GPL。两者均为开源软件，但如果以后将修改后的求解内核分发给其他公司或集成到产品中，许可证义务不同，需要公司进行合规审查。

## 四、我会怎样决定是否从 Meep 转向 FDTDX？

我不建议现在让 Codex 继续大规模改造 Meep，也不建议立即停止 Meep、全面改用 FDTDX。

**先给 FDTDX 做一次明确的对标测试。** 核心目的是验证它已有的非均匀网格，是否真的能够减少我们的开发量，并在同样精度下减少内存和总运行时间。

建议用三个递进案例：

| 验证案例 | 要检查的内容 | 转向判断 |
|---|---|---|
| 有损/色散平面薄膜 | 非均匀网格、复 r/t、PML、网格收敛 | 基础光学功能必须可靠 |
| 梯形侧壁 + Footing + 多层膜 | 三维界面映射、不同细网格、复反射相位 | 关键形貌必须能准确计算 |
| 小型有限三维 Mark | 空气侧复场、角谱、交叉偏振、内存与耗时 | 必须证明真实三维计算有工程收益 |

使用相同的几何、材料响应、源、参考面和误差标准进行对照。

初期可以把强散射通道的复振幅误差控制在约 1% 以内、重点相位误差控制在 0.05° 以内作为筛选目标。这些是待验证的工程目标，不是 FDTDX 或 Meep 已经达到的精度。对于有限 Mark，要在同一角度、同一偏振基底和同一参考面下比较连续散射复场，而不是强行按无限周期衍射级次比较。

同时必须统计完整运行成本，包括 JAX 首次编译、材料初始化、计算、监视器及数据传输，避免只比较核心时间步速度。

我会设置三个实际决策门槛：

| 条件 | 决策 |
|---|---|
| **FDTDX 精度通过，并且实际 GPU 能部署** | 将 FDTDX 确定为主研发后端。Meep 保留为独立交叉验证基准。 |
| **FDTDX 精度通过，但显存或计算环境不满足要求** | 使用 Meep 作为当前主要执行后端，保留 FDTDX 接口，避免立即投入更大规模的 FDTDX 优化。 |
| **FDTDX 非均匀网格或复杂界面精度不合格** | 优先分析是否是材料映射、源或界面问题。若涉及不可接受的核心缺陷，则继续使用 Meep，并据此决定是否值得推进现有 S2 分支。 |

## 五、对当前项目的具体建议

现在已有的 Meep S2 成果没有必要丢弃。它至少能够用于理解并验证三轴非均匀 Yee 离散和受限界面平均。

但是在 FDTDX 0.6.3 已有相应基础功能的情况下，**我不建议未经比较就继续花大量时间，为 Meep 从头集成非均匀 PML、源、监视器、MPI 和完整材料处理**。

从软件架构上，最稳妥的方案是将三维形貌与材料输入、FDTD 求解、复散射输出和量测信号分离，让 Meep 和 FDTDX 使用相同的上层接口。这样即使最终切换后端，也不需要重写形貌重建和光路模型。

**最终，我现在更倾向 FDTDX，但还没有足够证据将它正式锁定为唯一求解器。** 我建议下一项工作不是继续开发 Meep 的 S3，而是使用 FDTDX 0.6.3 跑通一个具有真实非均匀网格、倾斜侧壁和有损材料的小型三维 Mark，并与已收敛的 Meep/Lumerical 参考比较。

这项测试能够直接决定我们是否值得转向 FDTDX，比继续按软件功能数量评分更有价值。
